| 7 | **LangGraph** for orchestration; **official `mcp` Python SDK** for the server and client. | Required (LangGraph) and the reference implementation (MCP). |
| 8 | **Default LLM: `anthropic:claude-haiku-5-5`**; any `provider:model` string through `LLM_MODEL` (per-agent overrides available). | 9 | **Vector store: Qdrant in embedded (local) mode**, optional server through `QDRANT_URL`. | The assignment allows "another suitable vector database". | 11 | **No PyTorch at run time.** Embeddings, reranker and TTS run on ONNX Runtime; Whisper on CTranslate2. | Smaller install and image, faster cold start, same models. |
| 12 | **Voice is local-first:** faster-whisper for ASR, Kokoro-82M for TTS. OpenAI and ElevenLabs are drop-in providers. | No extra accounts or spend; works offline; the assignment's "such as" lists leave the choice open. |
| 13 | **Live search provider: Serper** (named in the assignment). Tavily, Brave and Claude's web-search tool sit behind the same interface. | Serper's shopping results return structured prices and ratings, which fit `{title, url, snippet, price?, availability?}` best; 2,500 free searches, no card. |

## Decisions taken while building

*(added as they happen, with the date)*

- **2026-11-10 — Claude 5.5 thinking control is per model.** The Models API reports which `thinking.type` each model accepts: Haiku 5.5 `disabled`/`adaptive`, Sonnet 5.5 `between_tools`/`adaptive`, Opus 5.5 `adaptive` only. The LLM factory picks the cheapest accepted setting per model instead of hard-coding one.
- **2026-11-10 — Kokoro speaks about 2.9 words per second** at speed 1.0 (43 words → 14.9 s), so a 15-second spoken summary is at most ~40 words. The limit is enforced on the synthesized audio's real duration, not on the word estimate.
- **2026-11-11 — The age field is not trusted on its own; ages stated in the listing text are reconciled with it.** The dataset's "Manufacturer recommended age" often says months where years are meant: a 402-piece K'NEX set is "7 months - 15 years" (its title says "Ages 7+"), a drinking game is "21 months - 3 years". Ages in titles and bullet points are parsed and reconciled with the field (title wins; a bullet point can only raise the minimum; a title never moves a product below three years against the field). 172 products had a field that contradicted the listing text by two years or more, and 311 products without the field gained an age. The evidence phrase is stored in `age_source`.
- **2026-11-11 — Under-three rule.** For a child younger than three, only products whose listing explicitly says they suit babies or toddlers are returned (427 of the 1,162 whose minimum age is under three), products with a small-parts, magnet, balloon or sharp-parts warning are excluded, products with no stated age are never admitted, and none of this is relaxed when results are scarce. Web results are not recommended for under-threes at all, because their suitability cannot be checked. Safety before recall.
- **2026-11-11 — The cross-encoder votes; it does not decide.** On the benchmark, ordering the 40 candidates by cross-encoder score alone was slightly *worse* than hybrid retrieval and cost about 3 s per query on the 2-CPU workspace. Re-ranking only the first 10 and fusing its ranking with the retrieval ranking (RRF) matched the best accuracy at a quarter of the cost, so that is the default (`RERANK_TOP_N`, `RERANK_WEIGHT`). The re-ranker's top score is also the "nothing relevant in the catalog" signal (`WEAK_MATCH_SCORE`). Numbers: `eval/results/retrieval/`.
- **2026-11-11 — Benchmark honesty.** The retrieval queries are written by an LLM from the target product's own listing, so they share its vocabulary and favour lexical search; "target in top k" is a lower bound because other products can be good answers too. The benchmark is used to compare variants, not as an absolute quality claim, and this is stated wherever the numbers appear.
- **2026-11-11 — The Planner writes the first tool calls; the Retriever model decides what follows.** Running the planned searches needs no model, so the Retriever model is only called when there is something to decide: a live price check, weak results, a failed call. When the planned results are strong and no live check was asked for, no model call is spent (the step log says why). This saves about a second per turn without making the loop less agentic.
- **2026-11-11 — Models choose and explain; code fills in the numbers.** The Answerer returns evidence handles (C1, W2) and reasons. The comparison table, citations, the count of alternatives in the spoken text, and every safety note are assembled by code from the evidence. Borrowed from how production shopping assistants "hydrate" answers from systems of record: a number on screen can never be something a model typed.
- **2026-11-11 — Rule checks are binding; the model critic is advisory about wording after one revision.** The first live runs showed the small model critic "finding" statements it had itself confirmed ("keep; the evidence supports this"), which sent good drafts back or replaced them with the template. Changes: the critic returns only must-fix findings in a structured form, entries that say no change is needed are set aside, and after one revision only rule violations and the critic's *unfit* / *safety* findings can still replace an answer. Replay on 12 logged drafts: 0 false alarms; on planted errors: 8 of 8 unsupported / wrong-age / invented-rating / absolute-safety claims and 6 of 6 unfit recommendations caught. `eval/experiments/critic_replay.py` re-runs logged critic calls against any prompt or model.
- **2026-11-11 — Structured output through forced function calling.** Measured on the real schemas, Claude's JSON-schema mode took 2.2–17.7 s on first use (the schema is compiled), a forced tool call 0.9–3.3 s. Latency matters more than strictness here because every output is validated by pydantic and has a rule-based fallback.
- **2026-11-11 — Refusals and emergency messages are fixed text.** A rule-based input screen runs before any model. It is tuned for precision on shopping language ("bath bomb kit", "water gun", "poison ivy costume", "Suicide Squad figure" all pass) and answers a possible poisoning emergency with the Poison Control number rather than a product or a refusal.
- **2026-11-11 — A rule-based version of every agent** exists as a fallback when a model call fails, as a complete offline mode (`LLM_MODEL=fake:rules`) for CI and demos without a key, and as the baseline the evaluation compares the LLM agents against.
- **2026-11-11 — Dependencies are locked.** `uv.lock` records the exact version of every package and the setup scripts install from it (`uv sync --frozen`). Found the hard way: the build workspace had a stray package (`langchain-mcp-adapters`, tried and not used) that silently held the MCP SDK at 1.30, while a clean install on the Mac resolved `mcp>=1.30` to 2.3, where `FastMCP` is renamed `MCPServer` and `McpError` is `MCPError`, so the MCP modules could not be imported. The ranges in `pyproject.toml` now also cap the major version of the libraries whose APIs the code uses in depth (MCP, LangGraph, LangChain, faster-whisper), and `scripts/mac_refresh.sh` prints the installed versions and imports the server, client and assistant before anything else runs.
- **2026-11-11 — The catalog build is reproducible byte for byte.** `voiceshop ingest` produced a `products.parquet` with the same SHA-256 (`527e2514…`) on Linux x86-64 and on macOS arm64; the index manifest records that hash, so an index can always be traced to the exact catalog it was built from.
